## Highlights

- Add **LAN only (no cloud access)** to the integration's Configure dialog: after one-time online provisioning, controls and native event handling start without cloud login, polling or command synchronization.
- Add **Philips Avent LAN Bridge 0.1.0** in this fork's App repository: direct LAN signaling/media, shared on-demand camera connections, copied H.264 video and AAC audio for Home Assistant playback.
- Automatically pass local media credentials and discovered addresses from the integration to the App; users do not copy keys or device IDs manually.

## Documentation

- [App setup and limitations](https://github.com/felixsteghofer/aventproxy/blob/v2026.10.0/aventproxy-lan-addon/DOCS.md) covers account provisioning, migration from the original WebRTC bridge and rollback.
- Point integration documentation and issue reporting at this maintained fork.

## Internal / dependency updates

- Preserve upstream password cleanup and recursive secret redaction; add protection for local media credentials.
- Build the camera client from pinned MIT-licensed source with timestamp/RTSP fixes and SHA-256-checked go2rtc downloads.
- Validate with 296 Python unit tests, 15 real-HA runtime tests with networking disabled, six App tests and native Docker build/reload checks.

## Upgrade notes

- Existing integration users: switch the HACS source to this fork, install v2026.10.0 and restart Home Assistant; retain the existing integration entry to preserve entity IDs and dashboards.
- New users: log in with the Philips Avent Baby Monitor+ email/password, country and emailed verification code, then enable LAN-only under Configure with bridge host `127.0.0.1`, port `38554` and talkback off.
- Stop the original WebRTC App before starting the LAN App because both use port 38554; enable automatic startup/watchdog after checking playback.
- Earlier local-prototype installations need the automatic media-provisioning step once when moving to this release; retain the original App for rollback until playback is verified.
- LAN media is experimental and tested on SCD923/26 with Tuya LAN 3.3. Real alarm delivery and reboot recovery with camera WAN blocked remain unverified. Initial provisioning and reset/re-pairing can require cloud access. Talkback is not implemented in the LAN App.
- No Home Assistant Core or OS upgrade is required.
